# IMSDA Events UI audit (mobile 390x844 + desktop 1280x800)

Base: origin/main 1e36ad8 (merge of PR #682). Next 16.3.6 dev server (webpack), Chromium via Playwright, synthetic data only.
Feeds issue #447 (mobile pass) and the full UI pass. Screenshots are kept locally by the automation session; none contain real data.

## Method and coverage
- 81 page/route combinations x 2 widths audited by script: horizontal overflow (`scrollWidth > innerWidth`), elements past viewport, interactive targets <44px, text <14px, tables vs. scroll containers, unlabeled controls, accessible names, heading order, computed focus styles (first 4 Tab stops), contrast (text vs first opaque ancestor bg), clipped overflow:hidden, JS errors. Plus visual review of ~25 screenshots.
- Sessions were minted directly in the DB (staff MFA and attendee 2FA bypassed; no code bypass exists). Seed added: 2 churches, 2 clubs, club profile, director/area/attendee accounts with active TOTP enrolment rows, 12 roster members, a CLUB event (copy of the WR26 form), registration window reopened. Seed data has no honors, orders, monthly reports, group setup or club registrations, so those pages were reviewed in their empty states only.
- Not audited / limits: (1) `/account/clubs/:id/events/:eventId` returned 500 ("column ClubRegistrationDraft.locationId does not exist") - this is an artifact of the shared node_modules Prisma client being generated from a different checkout, NOT an app bug; unaudited. (2) Group registration form itself (page shows the "not available yet" state, no group form configured). (3) Dev-only Next "N" badge overlaps the bottom nav "Home" label in shots; ignore. (4) Low-contrast numbers on gradient heroes (1.08:1) are script false positives (gradient background); hero text looks fine. (5) `scripts/refresh-local-demo.ts` fails on origin/main ("Church must use one of its configured choices") - README's `db:refresh-demo` step is broken with the current directory-backed church field (not UI, worth a separate fix).
- Good news: **no page has horizontal page scroll at 390px** (81/81). Every `<table>` either fits or sits in an `overflow-x:auto` wrapper (`.report-table-wrap`). No unlabeled form controls were found. One `<h1>` per page everywhere. All images have alt. Focus on links/buttons is a 3px solid outline.

## Severity counts
High 2, Medium 14, Low 9 (25 findings; F = finding id).

## HIGH

**F1. Registration form builder is not workable on a phone** - `/registration-builder?event=...` at 390. 197 interactive targets under 44px; per-field action buttons (Copy/Up/Down/Remove) are ~29px tall and their labels render at 8.6px; field summaries 8.6-10.6px; 72 distinct sub-14px text selectors; page is ~7,900px tall (15,754px at 2x). The nav marks this page `desktopOnly` yet it is reachable from More and renders the phone shell. Files: `components/registration-builder-workspace.tsx`; `app/globals.css` `.field-actions button` (l.2132-2142), `.field-module-summary` (l.2151-2156, small 0.54rem / strong 0.66rem), `.field-module-row .field-actions` (l.2543). Suggest: either a "best on a larger screen" gate for the builder on <768px, or 44px actions + >=12px text in a kebab menu.

**F2. Staff event picker is truncated to "W..." / "Wom..." on phones, and its width changes per page** - every staff route at 390 (`/people` 53px, `/registration-builder` 62px, `/finance` 83px, `/more/honors` 125px). Two events (Women's Retreat 2026 / Pathfinder Camporee 2026) are indistinguishable, so staff may edit the wrong event. `.mobile-event-picker` (`max-width:42vw`, globals l.2387-2412), `components/app-shell.tsx:261`. Suggest: move the picker to its own full-width row under the title, or show the event name as a sub-title with a tap-to-change control.

## MEDIUM

**F3. Sub-14px text is the norm on staff pages (and common on club/account pages)** - 72 of 81 mobile pages contain <14px text. Worst: form builder 72 selectors, registration detail 47, event settings 45, reports/exports 39, sys-admin 31, overview 30. Body is 15px, but labels/help/meta use rem values of 0.54-0.68 (8.6-10.9px): `.form-stack label` 0.7rem (11.2px; every staff form), `.field-help` 0.63rem (10.1px, l.1824), `.checkbox-label` 0.64rem !important (l.1802), `.count-badge` 0.68rem (l.1102), `.report-table thead th` 0.57rem = 9.1px and td 10.9px (l.5934), `.person-row small` (l.1048), eyebrows 10.6px, `.brand small` ("Events") 9.9px, status chips 9.8px, `.auth-form label` 11.2px on sign-in/sign-up/recover. There is a `--text-helper-min` token used only in one media query at globals l.8074; apply a >=12px (labels/body >=14px) floor globally at `max-width: 768px`.

**F4. Bottom nav labels 9.3px, contrast 3.4:1** - all staff pages at 390. `.mobile-nav a` (globals l.2419: font-size .58rem, colour #7d8e96 on white). Labels also differ from desktop names (People vs Registrations, Promos vs Promo codes, Home vs Dashboard). Raise to >=11-12px, darken to >=4.5:1.

**F5. Fix by darkening the `--muted` token in `:root` and the calendar/outside day colour.

**F6.
